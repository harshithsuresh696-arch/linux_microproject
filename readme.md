# Centralized Linux Backup System 🛡️💾

A secure, automated, centralized backup architecture deployed using Kali Linux virtual machines. This project utilizes `rsync` over SSH for secure data transfer, Logical Volume Management (LVM) for scalable storage, and strict firewall/permission configurations to harden the infrastructure.

## 🏗️ Architecture & Topology

The environment consists of three Kali Linux VMs running in VirtualBox, connected via an isolated Host-Only network adapter for internal traffic and a NAT adapter for internet access.

| Hostname | Role | IP Address (Host-Only) | Operating System |
| :--- | :--- | :--- | :--- |
| `backupserver` | Central Backup Server | `192.168.56.10` | Kali Linux |
| `client1` | Backup Client 1 | `192.168.56.11` | Kali Linux |
| `client2` | Backup Client 2 | `192.168.56.12` | Kali Linux |
| **Subnet** | Internal Backup Net | `192.168.56.0/24` | N/A |

## ✨ Key Features

* **Automated & Incremental:** Uses `cron` to schedule nightly backups and `rsync` to only transfer modified data, minimizing network load.
* **Secure Authentication:** Eliminates password-based logins in favor of `ed25519` SSH key pairs.
* **Hardened Security:** 
  * Uncomplicated Firewall (UFW) restricts incoming SSH traffic exclusively to the internal `192.168.56.0/24` subnet.
  * Root SSH login and password authentication are permanently disabled via `sshd_config`.
* **Scalable Storage:** A dedicated 50GB virtual drive is managed via LVM and formatted with `ext4`, allowing for dynamic resizing as storage needs grow.
* **Role-Based Access Control (RBAC):** Strict permissions (`2770`) and dedicated users/groups (`backupadmin` and `backupuser`) ensure only authorized accounts can access the backup pool.

## 🚀 Deployment Guide

### 1. Network & Core Services
Static IPs were assigned to the internal `eth0` / `eth1` interfaces using `nmcli`. Required packages were installed across all nodes:
```bash
sudo apt update && sudo apt install -y rsync openssh-server openssh-client cron lvm2 ufw
sudo systemctl enable --now ssh cron
```

### 2. User Management
* **On Server:** Created the `backupgrp` group and `backupadmin` user to manage the storage pool.
* **On Clients:** Created a limited `backupuser` account to own the data being backed up.

### 3. LVM Storage Setup (Server)
A secondary 50GB virtual disk (`/dev/sdb`) was initialized and mounted securely:
```bash
sudo pvcreate /dev/sdb
sudo vgcreate backupvg /dev/sdb
sudo lvcreate -l 100%FREE -n backuplv backupvg
sudo mkfs.ext4 -L BACKUPVOL /dev/backupvg/backuplv
sudo mkdir -p /srv/backups
sudo mount /dev/backupvg/backuplv /srv/backups
sudo chown -R backupadmin:backupgrp /srv/backups
sudo chmod 2770 /srv/backups
```

### 4. Passwordless SSH
An `ed25519` SSH key was generated by the `backupadmin` on the server and distributed to the clients using `ssh-copy-id`, allowing silent, secure background connections.

### 5. Security Hardening
* **Clients (`/etc/ssh/sshd_config`):** Set `PasswordAuthentication no` and `PermitRootLogin no`.
* **Server (UFW):**
  ```bash
  sudo ufw default deny incoming
  sudo ufw default allow outgoing
  sudo ufw allow from 192.168.56.0/24 to any port 22 proto tcp
  sudo ufw enable
  ```

### 6. The Automation Script
The following bash script (`run_backups.sh`) was deployed on the Server. It uses `rsync` over SSH to pull data from the clients' `~/important_data` directories into the LVM storage pool:

```bash
#!/bin/bash

# Define variables
SSH_KEY="/home/backupadmin/.ssh/id_ed25519"
DESTINATION="/srv/backups"

# Backup Client 1
echo "Starting backup for Client 1..."
rsync -avz -e "ssh -i $SSH_KEY" backupuser@192.168.56.11:/home/backupuser/important_data/ $DESTINATION/client1/

# Backup Client 2
echo "Starting backup for Client 2..."
rsync -avz -e "ssh -i $SSH_KEY" backupuser@192.168.56.12:/home/backupuser/important_data/ $DESTINATION/client2/

echo "All backups completed successfully!"
```

### 7. Cron Scheduling
The script is scheduled to run fully automated every night at 2:00 AM, logging its output for monitoring:
```bash
0 2 * * * /home/backupadmin/run_backups.sh >> /home/backupadmin/backup.log 2>&1
```
